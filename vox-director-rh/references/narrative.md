# 叙事层 Narrative — 弧线 / 钩子 / 节拍 / 运镜节奏

这是 `creative-mvp.md`（视觉 LOOK 层）的姊妹篇，管的是**故事骨架**：整片用什么叙事弧线、第一镜怎么钩人、一句旁白配几个画面、镜头景别和运镜怎么排才不闷。移植自上游 Vox Director 的 beat-layer，并按我们的现实条件裁剪：

- 中文旁白，支持 **15–60 秒**（`--duration` 接受 10–75，长片靠更多 beat）
- RunningHub 低价视频源片固定 **8 秒**，单段语音硬预算 **7.35s**（见 pitfalls 第 9 节），所以单个 beat 的旁白默认 4–7s，句子不随片长变长
- 省钱纪律：不自动重投；双镜头 beat 是可选项，不是必须

---

## 1. 三层分工

| 层 | 字段 | 谁决定 |
|---|---|---|
| 叙事弧线 arc | 整片一个 `arc` | AI 按主题推荐，**用户一键确认** |
| 每 beat 的旁白 + 画面标题 | `narration` / `headline` | AI 起草，**用户在分镜门审批/改写**（唯一强制门） |
| 景别 + 运镜 | `shot_size` / `camera_move` | 从受限词表 + 反单调规则推导，用户一般不用改 |

景别和运镜**不要自由发挥**——自由文本很容易冒出 orbit / dolly_zoom 这类会扭曲平面拼贴、糊掉文字的运镜。

## 2. 叙事弧线库 arc（按主题选一个）

| arc | 适用 | beat 走向（最短 4 beat 骨架） |
|---|---|---|
| `hook_payoff` | 单个观点、最安全的默认 | 钩子 → 背景 → 机制/展开 → 金句收尾 |
| `how_it_works` | 解释一个东西/系统/流程怎么运作 | 钩子 → 它是什么 → 关键 1–2 步 → 所以呢 |
| `timeline` | 历史、"…的演化"、来龙去脉 | 起点 → 发展 → 转折 → 现状/启示 |
| `myth_buster` | 纠正一个常见误解 | 先抛事实 → 常见错觉 → 拆穿 → 该信什么 |
| `pas` | 痛点广告、有紧迫感 | 痛点 → 放大痛点 → 解法 → 行动/好处 |
| `bab` | "after"比痛点更卖得动时 | 之前多糟 → 之后多好 → 怎么桥接 → 行动 |
| `man_in_hole` | 案例、逆袭、转变（最有代入感） | 本来挺好 → 掉坑 → 谷底 → 爬出来比以前更好 |
| `listicle` | "N 个方法 / N 个原因" | 承诺 → 逐条 → 最关键一条 → 回顾 |

> 上表是最短的 4 beat 骨架；长片由 `new_project.py` 内建的 12 段阶段表（`ARC_STAGES`/`ARC_MOVES`）均匀采样扩成 6/8/10/12 beat（如 60s `timeline` 展开为 钩子→起源→早期→发展→转折点→扩散→现状→启示）。
>
> 上游还有 `aida / storybrand / three_act / story_circle / story_spine / origin`，更适合长广告或品牌片；当前 15–60s 用上面 8 个已够，需要时再往 `ARC_STAGES` 补。

**主题→arc 直觉：** 产品/服务广告 → pas/bab；概念/原理 → how_it_works/hook_payoff；历史/"演化" → timeline；逆袭/案例 → man_in_hole；纠偏 → myth_buster；盘点 → listicle。

## 3. 钩子 hook（第一镜，≤3 秒定生死）

约 65% 的人在 3 秒内决定划走。**第一镜不要用来铺垫**，标题就要带着"回报承诺"。给第一镜的 `hook_type` 选一个：

| hook_type | 打法 | 中文示例（以"比特币"为例） |
|---|---|---|
| `direct_question` | 一个让人想知道答案的问题（默认好用） | "一串代码，为啥能卖几十万？" |
| `surprising_stat` | 反常识数字 | "2100 万枚，永远不会再多了。" |
| `mistake_callout` | "你一直以为…其实错了" | "你以为钱值钱是因为那张纸？" |
| `pain_point` | 直接戳痛点 | "钱放着，为什么会越来越不值钱？" |
| `secret_reveal` | 揭晓一个秘密/内幕 | "钱最大的秘密：它本身一文不值。" |
| `outcome_tease` | 先给结果吊胃口 | "看完你就懂为什么有人愿意囤它。" |
| `pattern_interrupt` | 反常画面/断言打断滑动 | （配合强视觉）"这玩意，曾经真的是钱。" |

底层就三招：好奇缺口、模式打断、大胆断言。

## 4. beat × shots：一句旁白配几个画面

- **一个 beat = 一句完整旁白 + 一条字幕**，旁白和字幕归 beat，不归单个画面。
- 一个 beat 可以有 **1–2 个视觉镜头（shot）**：
  - **单镜头 beat**（默认、省钱）：一句旁白配一张海报，靠元素运动+一个运镜撑住。多数 beat 用这个。
  - **双镜头 beat**（节奏升级）：一句旁白横跨两张海报、句中硬切——
    - 镜 a = **wide 主镜**：建立场景，`title_on_image=true`，标题在这一镜出现一次；
    - 镜 b = **detail 特写**：切到关键道具/数字/动作的特写，`title_on_image=false`，**不另配旁白**。

    这是上游验证过"性价比最高的节奏手段"，但每多一个画面就多一次关键帧+一次图生视频的钱。建议：**只在最需要强调的 1–2 个 beat 上加 detail 特写**（如机制 beat、金句 beat），不要全片翻倍。
- 单个视觉镜头在成片里通常 **3–5s**，再长 AI 运动就没地方去、显得死。切镜节奏：**每 3–5 秒画面要有变化，单张海报挂超过 ~7s 就闷**。
- 我们 8 秒源片预算下，双镜头 beat 的两个成片镜头都从各自的 8s 源片裁出（每段仍受 7.35s 语音预算约束，但只有 anchor 镜头产旁白）。

### 景别 shot_size（受限词表）

`WIDE`（主体在环境里，建立）· `MEDIUM`（一个主体居中，干活主力）· `CLOSE`（一个细节填满画面，强调/情绪）· `DETAIL`（单一纹理/词/数字，重音 beat）。

- 双镜头 beat 固定搭配：**a=WIDE（带标题）→ b=CLOSE/DETAIL（无标题）**。
- 整片景别要有推进：随弧线向高潮走 WIDE→MEDIUM→CLOSE；收尾可以 CLOSE→WIDE 拉开给启示。

## 5. 运镜 camera_move（受限词表，别自由发挥）

安全档（均匀平移/缩放，文字作为整体一起动，不会扭曲）：

| token | 画面效果 | 作用 |
|---|---|---|
| `static` | 不动，只有元素轻微浮动 | 让数字/金句落地，**留给收尾/金句 beat** |
| `push_in` | 均匀放大（Ken Burns） | 制造张力、聚焦 |
| `pull_out` | 均匀缩小 | 揭示全局、收尾 |
| `pan` | 横向平移（海报要做得超宽） | 读清单/时间线 |
| `tilt` | 纵向平移 | 表现规模/倒数 |
| `parallax` | 前中后景以不同速度错位 | "会呼吸的纸"招牌质感 |

> 大胆档 `orbit / dolly_zoom / roll / whip` 容易把平面艺术扭歪、文字糊掉，本版不开放；以后要做就加 `constraints: loose` + 接受重滚。

**反单调（最大的质量杠杆）：相邻两个镜头不许用同一个运镜**（anchor→detail、跨 beat 都算相邻），缩放族 ↔ 平移族 ↔ static 交替；`static` 留给最后的金句/论点 beat，运动一停就暗示"这是重点"。

运镜序列不用手排：`new_project.py` 按 `ARC_MOVES` 为每条弧线内置了 12 拍节奏，再按 beat 数均匀采样并自动修复相邻重复、强制收尾 static。4 beat 短片的落地节奏参考：

- `hook_payoff`：push_in → pan → parallax → static
- `how_it_works`：push_in → pan（步骤横向展开）→ parallax → static/pull_out
- `timeline`：pan 同向一路推进 → 转折点 push_in → 收尾 pull_out/static
- `myth_buster`：push_in（错觉）→ tilt → parallax（拆穿）→ static（真相）
- `pas/bab`：push_in → static → pan → parallax
- `listicle`：每条同一运镜（pan/tilt），#1 换方向；回顾用 static

## 6. 结尾 ending

| ending | 效果 |
|---|---|
| `hard_cut` | 在金句上硬切收尾（默认，利于重播） |
| `quick_cta` | ≤2s 一个行动 + 一个好处，3–5 个字 |
| `loop_close` | 最后一句呼应第一句，无缝循环重播 |

知识短片默认 `hard_cut`；广告片才用 `quick_cta`。

## 7. beat 节拍速查

| 成片 | beat 数 | 每 beat 成片时长 | 旁白字数（中文，参考） |
|---|---:|---|---|
| 15–22s | 4 | 4–5.5s | 12–22 字最稳 |
| ~30s | 6 | ~5s | 12–24 字 |
| ~45s | 8–10 | 5–6s | 12–24 字 |
| ~60s | 10–12 | 5–6s | 12–24 字 |

建项时 `--duration` 自动选 beat 数（≤22→4、≤32→6、≤42→8、≤52→10、更长→12）。单句硬上限仍是对应 7.35s≈30 字；**长片是 beat 更多，不是句子更长**。

比例：钩子 1–3s → 主体 70–80% → 金句/收尾 10–20%。

**字数是最便宜的质量开关**：想紧凑就把旁白压到 12–22 字；某一句信息优先允许写长（字幕靠 Pillow 90% 换行保持一行/紧凑两行），但别靠拉长单句凑整片时长——加 beat 才对。
